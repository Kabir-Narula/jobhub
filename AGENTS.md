# Project notes (jobhub)

Single-user job aggregation + application tracking + LaTeX resume tailoring. See README.md for setup.

- Next.js 16: `proxy.ts` (not middleware.ts), all request APIs async (`await params`, `await cookies()`).
- shadcn/ui here uses **Base UI** primitives (not Radix): `<Button render={<Link/>} nativeButton={false}>` instead of `asChild`, Select `onValueChange` receives `string | null`.
- Theme: warm-paper light, tokens in `app/globals.css` (accent `#c2410c`); display font Space Grotesk via `--font-space-grotesk` (`font-display` class).
- Prisma 6 (pinned; v7 has breaking changes). CLI reads `.env` only; Next reads `.env.local` — DB creds live in both.
- `lib/tailor/latex.ts` is the design lock: masters are parsed into frozen segments; the LLM produces JSON only; the assembler re-injects. Never let the LLM emit LaTeX.
- Tailoring v3: bullets written from scratch (3/entry), titles optimized by default (route `allowTitleChanges` defaults true), skills re-ranked within master vocabulary, best-2 projects from `lib/tailor/projects.ts` (grounded in the real repos). Fabrication tripwire = `findNewNumbers` (punctuation-normalized; trailing `+` stripped so `20+` matches `20`). Role family: `Junior Analyst Data CIB`-style titles are `analyst`, not SWE. Analyst audit is NOT consulting-partner CAR — data problem → method → who used it. Optional passes (compress / ATS boost / fill / repair) must not throw away a 1-page draft on quota errors.
- JD analysis (`lib/tailor/jd-analysis.ts`): every generation starts from a structured read of the posting — deterministic section parse + cheap-tier labels (domain, work types, seniority, **mustHaves/niceToHaves**). Cache is versioned (`JD_ANALYSIS_VERSION`); bump it when the meaning of must-haves changes. `cleanJobDescription` strips careers-site chrome before family detection and scoring. Scoring weights must-haves 3x and includes analysis phrases plus `PHRASE_EQUIV` (e.g. Microsoft 365 covers O365). ATS boost + quality repair share one quality-tier call when both are needed; a discarded boost must NOT skip the later repair. Uncovered must-haves join via `coverageIssues`. `match.ts` strips `\hypersetup` metadata before scoring, requires same-sentence proximity for multi-word terms, and drops never-invent vendors from claimable terms on business postings. Lens suppression governs emphasis only: JD-named terms are exempt on engineering resumes.
- Employer archetypes (`lib/tailor/hiring-screen.ts`): `detectEmployerArchetype(company, title, jd)` → bank-campus / fintech-scaleup / institutional-grad / econ-consulting / big4 / mbb-tier2 — the company's screen culture, orthogonal to posting flavor, applied to ALL role families via `hiringScreen` merge + an EMPLOYER LENS line appended to `lens_directive`. Screen content is grounded in official campus-program pages and recruiter guidance (see the file's comments).
- Bullet magnitude rule: EVERY expanded experience entry carries ≥1 numbered bullet suited to that entry's scenario (duration, count, rows/run, hours saved) from `metric_guidance.allowed_shapes`; the verbatim anchor entry is exempt; campus-ops uses real source counts. Enforced by `auditExperienceBullets` (high severity), fed to the repair pass.
- Master skills labels are canonical: `Languages` / `Infra & Tools` / `Frameworks` / `Cloud & Data` (`scripts/patch-master-skills-labels.ts`). JD_TECH_HOME and skills-extra assume exactly these. On consulting/analyst pages `pinBusinessSkills` regroups the same items under `Programming & Data` / `Analytics & Tools` / `Methods` / `Professional`.
- `normalizeForTectonic()` is idempotent (one XeTeX/glyph guard each). Apply at import time (seed + `/api/masters`); never re-apply in a loop on already-guarded masters.
- `fixEmptyLineBreaks()` runs inside `compileLatex` — required for masters that pdfLaTeX tolerated but XeTeX halts on.
- Source adapters: `lib/sources/*`, one shared `NormalizedJob` schema; failures isolated per source in `lib/poll.ts`. LinkedIn best-effort (disable `LINKEDIN_ADAPTER=off`). Workday: `limit` hard-capped at 20 by the API; boardToken = `host/tenant/site`.
- LLM: two tiers via `OPENAI_MODEL` (quality: first resume pass + compress/boost/repair, company research, interview prep, outreach email) and `OPENAI_MODEL_MINI` (cheap: JD-analysis labels, contact names, email interest paragraph). Refinement passes reuse `carryCoverLetter` so the letter is not rewritten 4 times. Any OpenAI-compatible API (`OPENAI_BASE_URL`; Kimi = `https://api.kimi.com/coding/v1` + `k3`). gpt-5.x rejects custom `temperature` — don't set it. `parseJson()` in research.ts tolerates ```json fenced replies. Email voice lives in `lib/tailor/email.ts`: code writes greeting + intro + recipient-kind ask (recruiter/campus → look at the application; everyone else → coffee chat/referral); the model writes only the "why this company" paragraph from `fetchCompanyNews` + research.
- Contacts: `lib/contacts/hunter.ts` (Hunter.io domain-search + verifier, role-ranked). Cached per company (sibling jobs reuse) to conserve the 25/month free quota. Route: `/api/contacts/find`.
- Verify changes with `npx tsc --noEmit`, `npx eslint .`, `npx tsx scripts/test-compile.ts`, `npx tsx scripts/test-tailor.ts` (fill % + frozen sections), and `node scripts/e2e-ui.mjs` (dev server running). Free deterministic suites (no LLM/DB cost): `test-match`, `test-jd-analysis`, `test-bullet-quality`, `test-tailor-quality`, `test-hr-tech`, `test-zs`, `test-hiring-screen`, `test-role-family`, `test-projects`, `test-pack`, `test-analyst-techniques`, `test-email-voice`, `test-dedupe`.
